# A. Multi-agent LLM trading frameworks and the evidence on LLM trading agents

Researcher agent (Opus 5.5), checked 2026-11-15. Repo numbers come from `gh api repos/OWNER/REPO`, `.../commits`, `.../releases` and `.../license` (the LICENSE file itself), all read on 2026-11-15. "Commits 6m" means commits on the default branch since 2026-05-15. Paper numbers come from the arXiv HTML/abstract pages linked; where I only had a secondary source this is said. Nothing was cloned or run.

**Corrections to the prior-art check in docs/IDEA.md (read these first)**
1. *"TradingAgents and ai-hedge-fund are backtest-only"* is **out of date**. TradingAgents v0.5.2+ has a headless CLI for scheduled jobs and a decision "memory log". ai-hedge-fund v2 (Nov 2026) now has **forward paper trading with a hash-chained, append-only ledger**, a daily runner and a trading-cost model.
2. *"Look-Ahead-Bench: most agents fail after their knowledge cutoff"* is **not what the paper says**. It is a one-author proof of concept: 5 big tech stocks, 2 six-month windows, agents built on ai-hedge-fund. Standard LLMs (Llama 3.1, DeepSeek 3.2) lose 15-22 percentage points of alpha after their cutoff, and the author's "point-in-time" commercial models (Pitinf) do not. Treat it as weak but directionally consistent evidence. The paper does not say whether the author is affiliated with the vendor.
3. *"StockBench: risk-adjusted gains but not total-return wins"* is **muddled**. In v2 (Mar 2026), Table 2 shows 11 of 13 models a little above buy-and-hold on return (+0.2 to +2.5% vs +0.4% over 4 months) and all of them with smaller drawdowns. Yet the abstract says most models fail to beat buy-and-hold. The gaps are tiny, there are only 3 seeds and 20 DJIA stocks, and no costs are modelled. The fair reading is "no meaningful edge either way".
4. *"CT Open, CC BY 4.0"*: CC BY 4.0 is the **licence of the arXiv paper**. I could not verify a licence for the CT Open data. Check it on ct-open.net before reusing anything.

### Per-project notes

**TradingAgents (Tauric Research).** This is a LangGraph graph that mirrors a trading firm. Four analysts (fundamentals, sentiment, news, technical) run in parallel. A bull and a bear researcher debate for N rounds, a research manager judges, the trader proposes, a three-way risk debate follows, and the portfolio manager approves. A "quick" and a "deep" model tier can each run on their own provider ([README](https://github.com/TauricResearch/TradingAgents#readme), paper [arXiv 2412.20138](https://arxiv.org/abs/2412.20138)).
- *Maturity:* maintained software. 90 test files under `tests/` (incl. `test_fundamentals_lookahead.py`, `test_memory_pointintime.py`), a CI gate since v0.3.0, Docker, releases roughly monthly ([tree](https://github.com/TauricResearch/TradingAgents/tree/main/tests)).
- *Claude:* native, via `langchain_anthropic.ChatAnthropic`, with the `effort` parameter ([anthropic_client.py](https://github.com/TauricResearch/TradingAgents/blob/main/tradingagents/llm_clients/anthropic_client.py)). A GitHub code search found no `cache_control` (prompt caching), no Batch API use and no token-cost tracking or budget cap. "budget" only appears as an SDK *retry* budget in `default_config.py`.
- *Forward running:* a headless CLI (`tradingagents --ticker X --date D --save --no-show`) and `ta.settle_all_pending()` "for a scheduled job". Since v0.5.0 it has point-in-time rules: SEC EDGAR fundamentals "as filed", Yahoo statements and insider trades withheld for past dates.
- *Decision store:* `~/.tradingagents/memory/trading_memory.md`. The module docstring calls it "append-only", but `update_with_outcome()` **rewrites the file** (temp file + `os.replace`) to swap the pending tag and add a reflection, and `_apply_rotation()` prunes blocks ([memory/log.py](https://github.com/TauricResearch/TradingAgents/blob/main/tradingagents/memory/log.py)). That **breaks our rule** that logged decisions are never edited. LangGraph checkpoints are per-ticker SQLite files.
- *Data:* yfinance (scraping Yahoo, unofficial, against Yahoo's ToS for automated use [unverified for 2026]), Alpha Vantage (proprietary freemium), SEC EDGAR (official, free), FRED (official, free), StockTwits/Reddit, Polymarket, an optional paid TypeSafe "Jev" screen.
- *Fit:* the architecture is one ticker → one decision, with analysts and decision layer welded into one graph. To share an analyst layer across 4 fund setups we would have to split the graph. LangChain/LangGraph add a big dependency tree and hide the raw Anthropic features we need (caching, batch, exact token usage).
- **Verdict: borrow the pattern.** Keep the role split (analysts → bull/bear debate with a capped number of rounds → judge → risk → PM), the quick/deep model tiers, the "settle decisions later and feed a short reflection back" loop (stored as *new* records, never edits) and its point-in-time data rules (EDGAR "as filed"). Write it ourselves on the plain Anthropic SDK, a few hundred lines.

**virattt/ai-hedge-fund.** In v2 (2026) this changed from a toy into a small, well-tested engine. Investor-persona LLM agents and strategy YAMLs (deep-value, earnings-drift, …) emit `{signal, confidence, reasoning}`, and a pipeline turns those into orders on a paper or simulated broker ([README](https://github.com/virattt/ai-hedge-fund#readme)). There is no LangGraph in v2: the LLM client is its own, with Anthropic as the default transport ([llm/client.py](https://github.com/virattt/ai-hedge-fund/blob/main/hedge_fund/llm/client.py)).
- *Maturity:* 44 `test_*.py` files and a PyPI package `aihf`. Still labelled "educational, proof of concept".
- *Forward running:* `aihf paper run <fund>` sleeps until the next session, advances one completed close at a time, catches up missed days "one honest session at a time" and never back-fills prices it did not see ([paper/runner.py](https://github.com/virattt/ai-hedge-fund/blob/main/hedge_fund/paper/runner.py)).
- *Decision store:* **one JSON file per session, each carrying the hash of the previous one**. Fund state is rebuilt by replaying the chain, an edited or reordered record breaks it, there is a `control.json` kill switch, and redone records move to `superseded/` instead of being deleted ([paper/ledger.py](https://github.com/virattt/ai-hedge-fund/blob/main/hedge_fund/paper/ledger.py)). In addition, every LLM call's exact prompt and response is stored as JSON keyed by hash(agent, model, prompt) ([llm/cache.py](https://github.com/virattt/ai-hedge-fund/blob/main/hedge_fund/llm/cache.py)).
- *Costs:* a trading-cost model with half-spread, $0.005/share commission, square-root market impact and a 0.5% no-trade band ([brokers/costs.py](https://github.com/virattt/ai-hedge-fund/blob/main/hedge_fund/brokers/costs.py)). The defaults are for liquid large/mid caps, so small biotechs need wider spreads. I found **no token-cost tracking or budget cap** (grep for usage/cost/budget in the LLM client), and no prompt caching or batch.
- *Data:* [Financial Datasets](https://financialdatasets.ai), a **proprietary paid API** (or pay-per-call in USDC via x402). This is the main blocker for reuse.
- **Verdict: borrow the pattern, not the library.** Copy three designs almost one-to-one: (1) the hash-chained per-session ledger with state rebuilt by replay, a kill switch, and "superseded" instead of delete; (2) the exact prompt+response record per LLM call; (3) the cost model with a no-trade band (re-parameterised for small-cap spreads). About 300-500 lines of our own code.

**FinRobot.** It has three generations: V0 AutoGen (educational, the paper [arXiv 2405.14767](https://arxiv.org/abs/2405.14767)), V1 on the OpenAI Agents SDK, and V2 "production" on PydanticAI + FastAPI + Tauri desktop. V2 has a lead agent, 5 sub-agents and a bull/bear/judge debate that produces 13-chapter equity reports ([README](https://github.com/AI4Finance-Foundation/FinRobot#readme)). It is an equity-research tool, not a fund. **Borrow one principle:** "Numbers are code-calculated. Narratives are LLM-assisted. Every output is provenance-tracked." Our rNPV, cash runway and dilution maths should be Python, never the LLM.

**FinGPT.** These are fine-tuned open financial LLMs plus data pipelines (MIT). It is not relevant to a Claude-based agent team. **Ignore.**

**FinMem** ([arXiv 2311.13743](https://arxiv.org/abs/2311.13743)). One agent with a "character" profile and a layered memory (short/mid/long-term, with decay). Abandoned since 2024. FINSABER re-ran it and its reported Sharpe of 2.68 fell to 0.93 on the same window (see A2). **Ignore the code.** The layered memory is an optional idea at most.

**FinAgent** ([repo](https://github.com/DVampire/FinAgent)). A multimodal (chart-reading) trading agent with reflection. Abandoned in 2024, OpenAI-only, and it needs 5+ proprietary data keys. **Ignore.**

**FinCon** ([arXiv 2407.06567](https://arxiv.org/abs/2407.06567), NeurIPS 2024). A manager-analyst hierarchy with "conceptual verbal reinforcement" (the manager distils lessons from episodes into beliefs). The README still says the code is unreleased because the data agent "relies on several commercial APIs". **Ignore**. The idea of distilling lessons is essentially TradingAgents' reflection.

**AI-Trader (HKUDS).** The repo started as the code for the AI-Trader benchmark paper ([arXiv 2512.10971](https://arxiv.org/abs/2512.10971), see A2). It is now an "agent-native trading platform" at ai4trade.ai, where agents register via a SKILL.md and publish or copy signals ([README](https://github.com/HKUDS/AI-Trader#readme)). It has no LICENSE file, so legally it is not open source despite the badge. It needs registration. **Ignore.**

**QuantAgent** (the URL now redirects to **QuantHarness**). LangGraph agents (indicator, pattern, trend, decision) for high-frequency, price-only trading from chart images. It supports Claude ([README](https://github.com/Y-Research-SBU/QuantHarness#readme)). It is the opposite of a fundamental biotech thesis. **Ignore.**

**StockAgent** ([arXiv 2407.18957](https://arxiv.org/abs/2407.18957), ACM TIST). LLM traders in a *simulated* market, used to study external factors. No licence file. **Ignore.**

**Vibe-Trading (HKUDS).** A very active, MIT-licensed personal trading agent: research reports, backtests, paper portfolios, "Swarm" committees, scheduled briefs, versioned research artefacts with evidence, and 28 market-data sources ([README](https://github.com/HKUDS/Vibe-Trading#readme)). It has 3,653 commits in 6 months (a churn risk) and leans towards China-market data. **Ignore as a dependency.** The idea of versioned research artefacts (a thesis is a dated, revisable document with linked evidence, and a revision is a new version) fits our thesis template.

**Alpha Arena-style clones.** [nof0](https://github.com/wquguru/nof0) (no licence, crypto/Hyperliquid, last commit 2025-12), [open-alpha-arena](https://github.com/etrobot/open-alpha-arena) (601 stars, no licence, crypto via ccxt). **Ignore.**

**HedgeAgents** ([project page repo](https://github.com/hedgeagents/hedgeagents.github.io), 31 stars, 2024). I found only a project page and no code. **Ignore** (unverified whether code exists elsewhere).

### What to build instead (synthesis for A1)
None of these fits our combination of rules: shared analyst layer × several decision setups, strict append-only log, token budget cap, Claude caching/batch, and biotech data (ClinicalTrials.gov, openFDA, EDGAR). All the mature ones either weld analysis and decision into one graph (TradingAgents) or depend on paid data (ai-hedge-fund, FinAgent, FinCon). **Recommendation: write our own small orchestrator on the plain Anthropic SDK** and borrow:
1. *TradingAgents*: role decomposition, bull/bear debate with capped rounds and a judge, quick/deep model tiers, delayed settlement + reflection (as new records), point-in-time data rules.
2. *ai-hedge-fund v2*: hash-chained per-session ledger + replay + kill switch + "superseded not deleted"; exact prompt+response record per call; trading-cost model with a no-trade band; a runner that never back-fills prices it did not see.
3. *FinRobot*: deterministic maths in code, LLM for narrative, provenance on every number.
4. Our own additions that nobody ships: a token ledger per call (input, output, cache-read and cache-write tokens → $) with a hard monthly stop; analyst outputs cached once per company per day and read by all fund setups; the Batch API for the nightly deep dives.

### Per-item details

**StockBench.** Top-20 DJIA by weight, $100k, daily signals (prices, fundamentals, news), 3 seeds averaged, **no trading costs** ([HTML v2](https://arxiv.org/html/2510.02209v2)). Table 2: Qwen3-235B-Think +2.5%, Claude-4-Sonnet +2.2%, GPT-5 +0.3%, GPT-OSS-20B −2.8%, against buy-and-hold +0.4% (max drawdown −15.2%). The universe size changes results a lot: Kimi-K2 gets −4.6% with 5 stocks, +3.2% with 10, −0.5% with 30. All agents lost to buy-and-hold in the downturn window and beat it in the upturn window, and one model went from last to first between those windows. Failure modes: arithmetic errors in share quantities, and JSON schema errors (more often in thinking models). Read it as: noise dominates, and results depend heavily on the setup.

**FINSABER.** FinMem's originally reported Sharpe on TSLA of 2.68 became 0.93 when re-run on the same window ([HTML v6](https://arxiv.org/html/2505.07078v6)). Over 2004-2024 on survivorship-free composites, buy-and-hold has a Sharpe of 0.70 against FinAgent's 0.24. Paired tests: buy-and-hold beats FinMem (p 3e-6 to 4e-5) and FinAgent (p 7.7e-4 to 0.012), and no LLM alpha is significant. By regime (average Sharpe): buy-and-hold 0.61 in bull / −0.28 in bear; FinAgent 0.12 / −0.38; FinMem −0.19 / −0.97. Recommendations: trend and regime awareness, risk control over complexity, and **include API costs in evaluation**.

**Look-Ahead-Bench.** As described in correction 2 ([HTML](https://arxiv.org/html/2601.13770v1)). Alpha decay: Llama 3.1 8B −17.2 pp, Llama 3.1 70B −15.3, DeepSeek 3.2 −21.8, Pitinf-S/M/L +0.3/+0.9/+1.3, momentum baseline −2.2. Monthly rebalancing, return-based only, a single author, and commercial "Pitinf" models. Weak evidence.

**Profit Mirage.** Same design as Look-Ahead-Bench, but with five published agent frameworks and windows chosen to have near-identical market returns ([HTML](https://arxiv.org/html/2510.07920v1)). The decay is large for every framework. Frameworks that use external tools decay a little less. The memorisation audit (85-93% recall of past market moves) is the most direct evidence that **backtesting a frontier LLM on any pre-cutoff period is meaningless**.

**DeepFund / LiveTradeBench / AI-Trader / AMA.** These are the live studies. All of them are short (2-10 weeks), use one live run per model (repeats are not reported in LiveTradeBench and AI-Trader), use tiny universes (5-15 stocks or index constituents) and **ignore trading costs** (LiveTradeBench and AI-Trader say so explicitly). Behaviour seen: over-adjustment and high volatility in reasoning models, overreaction to headlines (LiveTradeBench, the Oct 13 Polymarket episode), "hold-to-die" passivity, rigid target weights without liquidity awareness, overtrading (Gemini 2.5 Flash), and **single-source reasoning**: DeepSeek adopted one news story's thesis without checking it (AI-Trader, [HTML](https://arxiv.org/html/2512.10971v1)). Benchmark rankings flip between markets and between up and down windows.

**Alpha Arena.** I could verify only secondary press. The S1 ranking shows how a single short run with real money and leverage produces a headline ranking that says more about risk appetite than skill. nof1 itself has noted the setup's limits (short context, no memory, inability to scale positions; via [secondary summary](https://forklog.com/en/four-out-of-six-ai-models-suffer-losses-in-trading-tournament/)). Unverified at primary-source level.

**Forecasting benchmarks.** The transferable lessons are about *probability estimates*, which our thesis template asks for. (a) Live, post-cutoff questions are the only clean test. (b) Top bots ensemble several runs and models: the best Metaculus bot "aggregates over multiple runs", ensembles of 2-10 bots beat single bots and gains stop beyond about 10, and higher reasoning effort won 8 of 8 paired comparisons ([FutureEval post](https://www.lesswrong.com/posts/wZBbDqzfBjYG58CxK/futureeval-spring-results-pros-beat-bots-but-the-gap-is)). (c) Bot-makers advise "simplicity beats complexity" and "don't trust naive backtests". (d) Even at near-superforecaster level, models lag markets near resolution (Prophet Arena). For us that means the market price is a strong prior, and our "variant perception" claims should be rare and well argued.

**CT Open.** This is the only biotech-specific live benchmark, and its central result *is* look-ahead: Claude Opus 4.5 looks best on a window it may have seen and falls behind on the clean window, while a plain random forest stays steady ([HTML v2](https://arxiv.org/html/2604.16742v2)). Winter 2025: 314 trials; Summer 2025: 240 trials. It accepts open submissions (Summer 2026 Open). Data licence: check before use.

### Sceptical synthesis: what does the forward evidence actually show?

**1. There is no credible evidence that LLM trading agents beat a passive benchmark after costs.** Every clean (post-cutoff or live) study is short (≤ 4 months), uses ≤ 20 liquid large caps, runs each model once or three times, and ignores trading costs. Inside those studies, the outperformance is a few percent at most, flips sign between up and down windows, and differs more between markets and setups than between models. The long backtests that look good are contaminated: Profit Mirage reports 50-72% return decay after the cutoff, and FINSABER finds no significant alpha over 20 years. Most of this is preprints. Only FINSABER (KDD), DeepFund (NeurIPS D&B), CT Open (COLM) and the forecasting papers (ICLR) are peer-reviewed. Alpha Arena exists only in press coverage.

**2. Failure modes that recur across independent studies:**
- *Memorised outcomes and look-ahead.* Recall of past market moves is 85-93% (Profit Mirage); CT Open shows the same drop for trial outcomes. For us this also applies to **historical case studies inside prompts**: the model knows how famous biotech readouts ended.
- *Regime asymmetry.* Too cautious in bull markets and too aggressive in bear markets (FINSABER); all agents lost in the StockBench downturn window.
- *Overreaction and over-adjustment.* Reasoning models are more volatile (LiveTradeBench), chase headlines, and overtrade (AI-Trader).
- *Cost-blindness.* Almost no benchmark charges trading costs, so reported edges are upper bounds. Small biotechs have far wider spreads than DJIA stocks.
- *Single-source credulity and misread data* (AI-Trader, Prophet Arena). Arithmetic and schema errors (StockBench).
- *Run-to-run and setup variance.* Universe size alone swings results from −4.6% to +3.2% (StockBench); rankings reorder between windows (StockBench, AI-Trader).
- *General capability is not trading skill.* LMArena score vs return ρ ≈ 0.05 / −0.38 (LiveTradeBench); static QA scores don't predict trading (StockBench); the framework design matters more than the backbone (AMA).

**3. Design rules that follow for Bobby Hedgefund:**
1. **Forward only, and keep history out of the agents' scoring and, where practical, out of their prompts.** Never show the agents a past case whose outcome is public as if it were open. Use the historical case library for *human* learning and event statistics only.
2. **Point-in-time inputs with timestamps.** Every document the agents see carries its first-public timestamp (EDGAR acceptance time, ClinicalTrials.gov version date). Log the IDs of what was seen so any decision can be audited for leakage.
3. **Append-only ledger, hash-chained** (ai-hedge-fund pattern). Outcomes and reflections are new records that point to the decision, never edits. This is stricter than TradingAgents' memory log.
4. **Charge realistic costs per trade.** Use a spread from actual daily data or a conservative small-cap default (e.g. 50-100 bps round trip; my assumption, to calibrate), square-root impact and a no-trade band to stop overtrading. Report returns before and after costs.
5. **Baselines that matter:** XBI (equal-weight biotech, the real hurdle), IBB, IWDA, **the rule-based no-AI setup**, and a **random-entry baseline** (same universe, same position count and turnover, random picks; many seeds), so luck has a visible size.
6. **Repeat runs where it is cheap.** For the decision layer, run 3-5 samples per decision (or at least for a weekly sample) and log the spread. Treat large disagreement as low confidence and use it as an input to position size. Forecasting results suggest aggregating a few runs helps and more than about 10 adds nothing.
7. **Regime-aware risk rules in code, not left to the LLM.** These are FINSABER's main recommendation: exposure limits, maximum number of binary readouts at once, drawdown triggers.
8. **Deterministic numbers.** rNPV, runway and dilution are computed in Python (FinRobot principle). The LLM supplies probabilities and arguments, which are logged separately so they can be scored.
9. **Score probabilities, not only P&L.** Every thesis states a probability and date for its catalyst. Score those with the Brier score at resolution, against a base rate (e.g. phase-transition success rates) and the market-implied move. With ~100-300 catalyst calls in 6 months this is far more informative than portfolio returns. Optionally submit the clinical analyst's calls to CT Open.
10. **Put the token budget in the code**: a per-call token ledger and a hard stop. FINSABER explicitly asks for API costs in the evaluation, so report "alpha per dollar of tokens".

**4. What 6 months can and cannot show** (my own back-of-envelope estimate, not from a paper). A 20-30-stock small/mid-cap biotech portfolio plausibly has a tracking error against XBI of around 20-30% a year, so roughly 14-21% over six months. To be 2 standard errors from zero, a setup would need to beat XBI by roughly 30-40 percentage points in six months. So **six months cannot prove skill on portfolio returns**, and a "win" of +10% vs XBI is consistent with luck.
- It *can* show **large differences between setups**. These are paired comparisons that share the analyst layer and the market, so the noise partly cancels. Use the daily return *differences* between setups, not their levels.
- It can show **behavioural facts**: turnover, cost drag, discipline on exit rules, concentration in readouts.
- It can show **calibration of catalyst probabilities** over 100+ resolved events. That is the main scientific output.
- Pre-register the comparison metrics and the decision rule ("setup X counts as better if…") in the spec before going live, to avoid picking the winner after the fact.
